# API Endpoints

Mercenta provides a tiered API architecture for portal operations, machine integrations, autonomous AI agents, and cross-chain liquidity.

---

## 1. Aomi Agent & Autonomous Skill APIs

Public programmatic interfaces for autonomous AI agents, Claude Code, Cursor, OpenCode, Hermes, and `build.aomi.dev`:

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/api/aomi/manifest` | Returns Aomi App manifest, contract addresses, and tool schemas |
| POST | `/api/aomi/tools` | Dispatches autonomous tool execution (`mercenta_catalog`, `mercenta_quote`, `mercenta_checkout`, `mercenta_treasury_sweep`, `mercenta_crosschain_topup`) |

---

## 2. Treasury & Liquidity Routing APIs

Programmatic liquidity management, cross-chain deposit routing, and automated yield sweeps:

| Method | Endpoint | Description |
| --- | --- | --- |
| POST | `/api/treasury/sweep` | Executes autonomous yield sweeps of idle revenue into Morpho Blue Arc Vault with reserve floor protection |
| GET | `/api/liquidity/crosschain-quote` | Calculates zero-slippage Circle CCTP V2 deposit quotes (Base, Solana, Arbitrum, Polygon, Ethereum → Arc) |

---

## 3. Telegram Commerce APIs

APIs powering `@mercentabot` and the mobile Telegram Web App storefront:

| Method | Endpoint | Description |
| --- | --- | --- |
| POST | `/api/telegram/bot` | Telegram Webhook handler for bot commands, language toggle, and deep-linking |
| GET | `/api/telegram/orders` | Retrieves authenticated mobile order history and delivery verification status |

---

## 4. Integration API (Scoped API Keys)

Protected by HMAC and API keys configured in the merchant portal:

| Method | Endpoint | Scope |
| --- | --- | --- |
| GET | `/api/v1/account` | `account:read` |
| GET | `/api/v1/dashboard?period=30d` | `account:read` |
| GET | `/api/v1/orders?period=all&page=1&pageSize=25` | `orders:read` |
| POST | `/api/v1/orders` | `orders:create` |

Example test order body:

```json
{
  "requestId": "00000000-0000-4000-8000-000000000001",
  "productId": "test-creator",
  "quantity": 1,
  "reference": "my-test-1"
}
```

Generate a new UUID for each distinct request. Retrying the same request uses the same UUID and unchanged body.
