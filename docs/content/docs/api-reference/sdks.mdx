# SDK & Agent Tooling

Mercenta provides client packages and agent skill manifests for programmatic procurement, machine checkout, and storefront deployment.

---

## 1. Official Aomi Agent Skill (`@mercenta/aomi-skill`)

The canonical agent skill package provides a typed TypeScript client and manifests for autonomous assistants:

```bash
# Add skill to Claude Code, Cursor, Codex, OpenCode, or Hermes
npx skills add rdmbtc/mercenta

# Or install the TypeScript package directly
npm install @mercenta/aomi-skill
```

* **Standard**: Compliant with `aomi-labs/skills` and `build.aomi.dev`.
* **Autonomous Tools**: `mercenta_catalog`, `mercenta_quote`, `mercenta_checkout`, `mercenta_treasury_sweep`, `mercenta_crosschain_topup`.
* **Detailed Documentation**: See the [Aomi Agent Skill Guide](/docs/agents/aomi-skill).

---

## 2. Server Integration & HTTP APIs

For custom backend pipelines, Mercenta exposes standard REST endpoints authenticated with scoped API keys. Keep API keys strictly server-side and configure reasonable request timeouts:

* **Endpoints Reference**: [API Endpoints](/docs/api-reference/endpoints)
* **Authentication**: [API Authentication Guide](/docs/api-reference/authentication)
* **Swagger / OpenAPI**: [Interactive Specification](/docs/api-reference/swagger)

Circle App Kit and the Viem adapter are server integration dependencies. Human wallet signatures or deterministic policy engine clearances are required for blockchain execution. No model receives an unconstrained wallet private key.

## 3. Telegram Storefront Starter

To launch a branded RU/EN bot, see the [Telegram shop starter guide](/docs/guides/telegram-shop). It includes a standalone download, public branding configuration, Python/SQLite long polling, and a hardened VPS systemd service example.

---

## 4. Supply & Fulfillment Boundaries

Internal supply integrations are represented strictly as Wholesale Provider or Fulfillment Gateway. Proprietary vendor credentials, upstream account keys, and direct supplier identities are shielded behind the secure execution vault and are never exposed across public API contracts.
