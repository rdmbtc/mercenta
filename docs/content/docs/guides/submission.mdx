# Intent, confirmation, evidence.

Mercenta's submission scenario connects a bounded commerce proposal, a checked Circle payment and profit-allocation evidence. Digital goods remain simulated; testnet USDC transfers are real test transfers.

## Rehearse the flow

1. Sign in with the designated owner wallet. Do not paste private keys into the agent.
2. Ask `Plan a creator purchase under 2 USDC`. Review the budget, pinned quote and policy checks in Guided Demo. A message alone does not purchase.
3. Ask `Prepare a paid margin report`. The agent prepares a quote for the **Mercenta-owned** x402 demo service at **0.001000 test USDC**. Exact amount/recipient confirmation is separate.
4. Inspect the returned report and payment evidence. Gateway acceptance is not final Arc settlement. Reconcile the original authorization; do not create a replacement payment to retry.
5. Use a separately verified buyer transfer for sale-linked Profit First. Funding the account is not a sale. Contract allocation requires owner wallet signatures.
6. Show retry/restart tests as mocks, unless the same behavior was actually recorded against a live payment.

## The report is a scenario, not revenue

The fixed example uses declared gross 2.000000 USDC, procurement cost 1.532000, other assumed fees 0.005000 and report fee 0.001000. Allocatable margin is 0.462000; a 10% profit allocation would be 0.046200.

Buying this calculation does not purchase a supplier product, prove a customer sale or create investment yield. The service is operated by Mercenta; internal demo activity is not external adoption.

## Evidence checklist

- Public source repository and a recording under three minutes.
- Deployed app and documentation links.
- Exact transaction IDs and payment evidence; pending versus final clearly labelled.
- Test results for duplicate confirmation, disk restart, stale quote, wrong actor and insufficient funds.
- Actual business/pilot counts and value moved, separated from project-owner test funding.
- No secrets in git/history, recordings or browser payloads.

Live Earn, mainnet funds and real supplier fulfillment are outside this demo. Credentials previously disclosed in chat must be rotated before a production/mainnet launch.
