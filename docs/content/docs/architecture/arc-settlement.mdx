# Arc Network Settlement Architecture

Mercenta operates an institutional dual-network clearing architecture across **Arc Mainnet** and **Arc Testnet**, enforcing receipt-based verification and deterministic cryptographic finality before ledger crediting.

## 2. Evidence Before Credit Invariant

Direct deposits and machine checkouts strictly verify:
1. **Chain ID Verification**: Prevents cross-network replay attacks between Testnet (5042002) and Mainnet (5042).
2. **Receipt Success Flag**: Transaction execution status `1` (Success) confirmed by JSON-RPC.
3. **Canonical Block Hash**: Confirmed against the current canonical chain tip with at least 2 confirmations.
4. **Amount & Precision Invariant**: Native USDC has 18-decimal transport precision; Mercenta validates exact 6-decimal monetary units. Fractional micro-unit discrepancies are rejected rather than silently rounded.
5. **Nonce & Hash Uniqueness**: Transaction hashes are indexed uniquely across account deposits, order payments, and treasury sweeps in the append-only SQLite ledger.

---

## 3. Atomic Checkout & Non-Custodial Security

* **No Server-Side Custody**: The backend never holds customer private keys and does not sign transactions on behalf of users.
* **Deterministic Policy Gates**: Transactions must pass all 5 gates (Gross Margin Floor $\ge 15\%$, Auto-Approval Cap, Spend Velocity Cap, Invariant Solvency, Nonce Idempotency) before a signed quote is created.
* **Cryptographic Receipts**: Every completed settlement generates a tamper-proof SHA-256 state proof linking the on-chain transaction hash to the wholesale voucher fulfillment digest.
